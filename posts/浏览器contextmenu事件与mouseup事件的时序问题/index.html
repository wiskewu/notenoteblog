浏览器contextmenu事件与mouseup事件的时序问题

2026/10/16 15:08:5916 分钟阅读
BrowserWindowsKylin

背景

在开发过程中遇到一个问题，在 Windows 环境下的浏览器中，DOM原生事件 contextmenu 和 mouseup 事件的触发顺序是 mouseup 先触发，contextmenu 后触发。 而在 Kylin 环境下的浏览器中，contextmenu 先触发，mouseup 后触发。 后来多处查证，发现是平台差异问题，且该问题存在很长时间了，此处对这个问题进行记录。

最小复现路径

复制以下内容至 HTML 文件中，在 Windows/Kylin 环境下打开，右键点击页面，查看控制台输出。

<div class="card">
  <h2>原生事件顺序探针</h2>
  <p class="note">在蓝色区域<b>右键</b>，脚本仅用原生 <code>addEventListener</code> 在 <code>document</code> 上记录 <code>mousedown / mouseup / contextmenu</code> 的派发顺序。已对 <code>contextmenu</code> 调用 <code>preventDefault()</code>，避免弹出系统右键菜单干扰后续 <code>mouseup</code> 的观察。</p>
  <div id="target">在此处右键 → 查看顺序</div>

<script>
(function () {
  const t0 = performance.now();
  const doc = document;
  const logEl = document.getElementById('log');
  const verdictEl = document.getElementById('verdict');
  let win = []; // 一次物理按键窗口内的事件序列

  function push(type) {
    const div = document.createElement('div');
    div.innerHTML = '<span class="t">' + (performance.now() - t0).toFixed(1) + 'ms</span>' + type;
    logEl.appendChild(div);
    win.push(type);
  }
  function judge() {
    const i = win.indexOf('contextmenu');
    const j = win.indexOf('mouseup');
    const ctxFirst = i !== -1 && (j === -1 || i < j);
    verdictEl.innerHTML = '本机顺序：<b>' + win.join(' → ') + '</b> —— ' +
      (ctxFirst ? '<b>contextmenu 先于 mouseup</b>' : '<b>mouseup 先于 contextmenu</b>');
  }

  doc.addEventListener('mousedown', function () { win = []; push('mousedown'); });
  doc.addEventListener('mouseup', function () { push('mouseup'); });
  doc.addEventListener('contextmenu', function (e) {
    e.preventDefault();               // 阻止弹出系统右键菜单
    push('contextmenu');
    judge();
  });

  window.clearLog = function () { logEl.innerHTML = ''; win = []; verdictEl.innerHTML = '等待在蓝色区域右键…'; };
})();
</script>
</body>
</html>

分析

w3c规范说明

根据w3c规范，规范明确表示contextmenu事件的触发时机可能早于mouseup事件，也可能晚于mouseup事件：

When the contextmenu event is triggered by right mouse button, the contextmenu event MUST be dispatched after the mousedown event.

Depending on the platform, the contextmenu event may be dispatched before or after the mouseup event.

MDN-contextMenuShowEvent

根据MDN-contextMenuShowEvent文档说明，contextMenuShowEvent用于决定contextmenu事件触发时机是在mousedown事件之后，还是在mouseup事件之后。

在 Windows 上，这个默认值是"mouseup"，而在 macOS 和 Linux 上，这个默认值是"mousedown"。

Its underlying value is a string that may be either "mouseup" or "mousedown".

The default value is "mouseup" on Windows, and "mousedown" on macOS and Linux. Assigning to it on Windows has no effect - the setting is only designed to allow the context menu to be opened on mouseup instead of mousedown, not the inverse.

Mozilla Firefox

在Mozilla社区论坛的用户反馈的问题Left-clicking and right-clicking while holding the left button triggers an odd selection mode: deactivate this?，有人回复：

文中链接对应到 Firefox 的源码StaticPrefList中，提供了一个ui.context_menus.after_mouseup配置项，用于决定contextmenu事件触发时机是在mousedown事件之后，还是在mouseup事件之后。

# Whether context menus should only appear on mouseup instead of mousedown,
# on OSes where they normally appear on mousedown (macOS, *nix).
# Note: ignored on Windows (context menus always use mouseup).
- name: ui.context_menus.after_mouseup
  type: bool
  value: false
  mirror: always

总结

W3C UI Events 规范不约束contextmenu 必须在 mouseup 之后触发；

MDN、StackOverflow、Mozilla Bugzilla 均记录： Windows 平台浏览器右键菜单默认 mouseup 触发，Linux（X11/GTK/KDE，含麒麟桌面）原生惯例按下（mousedown）唤起上下文菜单，导致 contextmenu 事件在 mouseup 之前派发；同 Blink 内核在 Windows/Linux 宿主上可出现不同事件时序，属于符合规范的 UA 平台相关行为差异。
