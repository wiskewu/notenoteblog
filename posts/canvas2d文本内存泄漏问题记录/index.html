Canvas2D文本内存泄漏问题记录

2026/5/26 19:55:3323 分钟阅读
JavascriptPerformance

在使用paperjs过程中，遇到了一个棘手的内存泄漏问题，在此记录一下问题现象和排查记录。

背景

基于paperjs封装了一个绘制库PainterLib，编写一个组件CanvasChart，在这个组件中使用PainterLib渲染流程图。

然后在一个页面中，渲染一个CanvasChart组件A，和一个弹出式的CanvasChart组件B。

组件A渲染一副流程图存档，存档规模为：

维度 信息
存档大小 1920x1080
画面缩放 根据容器自适应，保持宽高比
画面规模 1000个组合图元，每个组合图元包含一个文本图元和一个圆形；画面中另有一个矩形，使其16ms触发画面更新（比如可视动态，或编写脚本定时器触发）

组件B渲染一副流程图，存档规模为：

维度 信息
存档大小 400x600
画面规模 无需特殊说明，可随意绘制若干个不同类型的图元

Note

组件A的画面表现为每16ms进行一次全量绘制，画面中除了矩形每帧切换显隐之外，其他图元属性均未变化。

测试场景

打开组件A，静置。

组件B通过第三方点击工具进行自动化操作弹出，脚本的周期为：

弹出组件B -> 等待1000ms -> 关闭组件B -> 等待1000ms
继续上述循环

现象

基于上述场景演化（实际业务场景），运行1H。

可以看到，CommitSize（提交内存）和WorkingSet（工作内存）阶梯式突变。

通过chrome://tracing记录数据如下：

可以看到，pooled_size和committed_size均已达到3G，而v8内存仅有600M左右。

分析

根因

采用控制变量的形式，修改源码进行以下测试（每行为一个单独的修改用例，无关联关系）：

修改内容 修改细节 是否存在内存泄漏
基于 paperjs 简化PainterLib库 -- 是
基于 zrender 简化PainterLib库 启用脏区重绘 否
基于 zrender 简化PainterLib库 未启用脏区重绘 否
基于原生 canvasAPI 简化PainterLib库 绘制逻辑参考paperjs 是
基于原生 canvasAPI 简化PainterLib库 绘制逻辑参考paperjs，将文本逻辑逻辑更改为绘制线条 否
基于原生 canvasAPI 简化PainterLib库 每帧只调用一次ctx.save+ctx.restore函数 否
修改paperjs源码 文本图元绘制时跳过ctx.save和ctx.restore调用 否

基于以上用例，分析得出：

  • paperjs 全量绘制模式下，每帧调用 ctx.save+ctx.fillText+ctx.restore，在高压绘制情况下（比如每帧16000次调用，每次调用这三个函数），会产生内存泄漏问题；
  • 在每帧绘制前调用ctx.reset，无法解决上述场景的内存泄漏问题；
  • 使用原生 canvasAPI 参考 paperjs 全量绘制模式，每帧调用 ctx.save+ctx.fillText+ctx.restore，也会出现内存泄漏问题；
  • zrender 全量绘制或者脏区局部绘制，均未观测到内存泄漏问题；
  • 使用原生 canvasAPI 参考 zrender 全量绘制模式，每帧调用一次 ctx.save+ctx.fillText+ctx.restore，未观测到内存泄漏问题；
  • 修改paperjs源码，在绘制文本前后跳过ctx.save+ctx.restore，未观测到内存泄漏问题。

综上，找到泄漏的原因是: ctx.save() + ctx.fillText() + ctx.restore()这三个API组合使用且高频绘制时，就会出现内存泄漏问题。

paperjs对于上述场景图元层级如下:

Project
  Layer
    Group
      PointText
      Shape(type='circle')

其绘制逻辑如下:

CavasView.update()
└── Project.draw()
    ├── ctx.save()
    ├── children[i].draw() (即Layer.draw，由于Layer extends Group extends Item，实际调用Item.draw)
    │   ├── ctx.save()
    │   ├── this._draw() (实际调用Group._draw)
    │   │   ├── children[i].draw() (即Group.draw，由于Group extends Item，实际调用Item.draw)
    │   │   │   ├── ctx.save()
    │   │   │   ├── this._draw() (即Group._draw)
    │   │   │   │   └── children[i].draw()
    │   │   │   │       ├── i=0
    │   │   │   │       │   ├── ctx.save()
    │   │   │   │       │   ├── this._draw() (即PointText._draw)
    │   │   │   │       │   │   └── ctx.fillText()
    │   │   │   │       │   └── ctx.restore()
    │   │   │   │       └── i=1
    │   │   │   │           ├── ctx.save()
    │   │   │   │           ├── this._draw() (即Shape._draw)
    │   │   │   │           └── ctx.restore()
    │   │   │   └── ctx.restore()
    │   └── ctx.restore()
    └── ctx.restore()

几个关键函数的源码为：

  1. CanvasView.update
  2. Project.draw
  3. Group._draw
  4. Item.draw
  5. PointText._draw

对照

对照zrender的全量绘制源码：

 // Paint all once
ctx.save();
this._paintPerCursorInRect(layer, layerCursor, list, null, contentRetained);
ctx.restore();

zrender 采用的是自己管理每个图元上下文状态，在一次全量绘制中只调用一次ctx.save和ctx.restore，相比于paperjs，每帧减少了大量的ctx.save和ctx.restore调用。

尝试将上述场景的底层渲染绘制库更换成 zrender，测试后未发现虚拟内存泄漏的场景，且占用内存更低。

其他说明

尝试修改 paperjs - Item.draw 源码，对文本图元的绘制采用手动管理文本上下文状态的方式：

# Item.draw
draw: function(ctx, param, parentStrokeMatrix) {
    // 省略原有逻辑
 
    var skipSaveRestore = direct && this._class === 'PointText'
                && normalBlend && opacity === 1
                && !param.clip;
    if (skipSaveRestore) {
        var prevTransform = ctx.getTransform();
        var prevFillStyle = ctx.fillStyle;
        var prevStrokeStyle = ctx.strokeStyle;
        var prevLineWidth = ctx.lineWidth;
        var prevLineJoin = ctx.lineJoin;
        var prevLineCap = ctx.lineCap;
        var prevMiterLimit = ctx.miterLimit;
        var prevFont = ctx.font;
        var prevTextAlign = ctx.textAlign;
        var prevShadowColor = ctx.shadowColor;
        var prevShadowBlur = ctx.shadowBlur;
        var prevShadowOffsetX = ctx.shadowOffsetX;
        var prevShadowOffsetY = ctx.shadowOffsetY;
        var prevLineDash = ctx.getLineDash();
        var prevLineDashOffset = ctx.lineDashOffset;
 
        matrix.applyToContext(ctx);
        this._draw(ctx, param, viewMatrix);
 
        ctx.setTransform(prevTransform);
        ctx.fillStyle = prevFillStyle;
        ctx.strokeStyle = prevStrokeStyle;
        ctx.lineWidth = prevLineWidth;
        ctx.lineJoin = prevLineJoin;
        ctx.lineCap = prevLineCap;
        ctx.miterLimit = prevMiterLimit;
        ctx.font = prevFont;
        ctx.textAlign = prevTextAlign;
        ctx.shadowColor = prevShadowColor;
        ctx.shadowBlur = prevShadowBlur;
        ctx.shadowOffsetX = prevShadowOffsetX;
        ctx.shadowOffsetY = prevShadowOffsetY;
        ctx.setLineDash(prevLineDash);
        ctx.lineDashOffset = prevLineDashOffset;
        // 沿用旧逻辑，恢复到父级矩阵状态参数
        matrices.pop();
        return;
    }
    // 原有逻辑
    ctx.save();
    // ...
    this._draw(ctx, param, viewMatrix, strokeMatrix);
    ctx.restore();
}

其中，部分状态未纳入管理范围，未管理的状态有：

  • clip裁剪区域：需通过save和restore；
  • globalAlpha：opacity=1，无需设置。前一个图元如果设置了透明度，也会自动restore恢复；
  • globalCompositeOperation，无需设置。前一个图元如果设置了合成模式，也会自动restore恢复;
  • textBaseline：绘制文本未涉及;
  • direction：绘制文本未涉及;
  • imageSmoothingEnabled：绘制文本未涉及;

这种方式下，若画面中所有文本都是挂载在Layer下，则内存泄漏问题得以控制，但不符合实际使用场景。 实际使用场景必然存在文本与其他图元组合的情况，这种情况下，手动管理文本上下文状态无法避免 Group.draw() 本身调用ctx.save和ctx.restore函数，结合文本图元的ctx.fillText，依然会出现内存泄漏。

手动管理状态的实现细节

根据CanvasRenderingContext2D：save() 方法描述，保存到栈中的绘制状态状态由以下部分组成：

  • 当前的变换矩阵；
  • 当前的剪切区域；
  • 当前的虚线列表；
  • 以下属性当前的值：strokeStyle、fillStyle、globalAlpha、lineWidth、lineCap、lineJoin、miterLimit、lineDashOffset、shadowOffsetX、shadowOffsetY、shadowBlur、shadowColor、globalCompositeOperation、font、textAlign、textBaseline、direction、imageSmoothingEnabled

可以按照下列方式进行划分：

类别 受影响的属性/状态 作用描述
变换（Transformations） 变换矩阵（Transformation Matrix） 由translate()、rotate()、scale()、transform()、setTransform()产生的当前画面坐标系的位移、旋转和缩放状态。
裁剪（Clipping） 裁剪区域（Clipping Region） 由clip()方法创建的当前裁剪范围。恢复状态可以取消当前的裁剪限制。
虚线列表 / 由setLineDash()设置的虚线列表样式。可以通过getLineDash()获取当前的虚线列表。
颜色与样式 fillStyle 当前用于填充的颜色、渐变或图案。
颜色与样式 strokeStyle 当前用于描边的颜色、渐变或图案。
全局显示配置 globalAlpha 全局透明度。
全局显示配置 globalCompositeOperation 全局合成操作（新旧图形的混合模式，如 source-over 等）。
线条配置 lineWidth 线条宽度。
线条配置 lineCap 线条端点样式（butt, round, square）。
线条配置 lineJoin 线条交汇处样式（round, bevel, miter）。
线条配置 miterLimit 斜接限制。
线条配置 lineDashOffset 虚线偏移量（注：setLineDash() 设置的虚线模式在某些旧浏览器中不被保存，但在现代标准中已纳入）
阴影配置 shadowBlur 阴影的模糊级别。
阴影配置 shadowColor 阴影颜色。
阴影配置 shadowOffsetX 阴影水平偏移量。
阴影配置 shadowOffsetY 阴影垂直偏移量。
文本配置 font 字体设置（大小、行高、字体族等）。
文本配置 textAlign 文本水平对齐方式。
文本配置 textBaseline 文本垂直基线对齐方式。
文本配置 direction 文本排版方向（如 ltr, rtl）。
图像平滑 imageSmoothingEnabled 图像缩放时的平滑处理开关（抗锯齿）。
