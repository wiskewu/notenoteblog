在工作流中使用Git worktree

2026/8/28 14:48:5111 分钟阅读
Git

基本概念

git worktree是Git2.5 版本就已提供的功能，允许同一个Git仓库，拥有多个独立工作目录。

  1. 主工作树（main worktree）: 原始项目目录，包含完整的.git仓库数据库。
  2. 链接工作树（linked worktree）: 通过git worktree add创建的额外目录，与主工作树共享同一套提交历史、对象数据库，但每个目录有自己独立的工作文件。

目录结构示例：

~/Herd/
├── my-project/        # 主工作树，main分支，包含 .git
├── my-project-feature/# 链接工作树，feature/login-form分支
└── my-project‑hotfix/ # 链接工作树，hotfix/payment‑bug分支

与传统分支切换的区别

传统方式：单项目目录，使用git checkout+git stash在分支之间来回切换。遇到紧急bug打断开发流程，容易丢失未提交的改动。

worktree方式：每个分支对应独立目录，多个分支可以同时打开、编辑、提交、推送，不需要来回切换分支。

[note] 限制 同一个分支不能同时在多个worktree检出，每个worktree必须绑定不同分支。 最佳实践：一个任务、一个分支、一个项目目录。

适合使用worktree的场景为：

  • 需要并行处理多个任务：新功能开发+历史版本bug修复；
  • 不想频繁被打断，不想使用stash暂存修改到一半的代码；
  • 需要同时打开多个分支代码做对比。

典型的worktree场景如：

  1. 正在feature/checkout做新功能，代码还没完成，无法生成一次有效的提交；
  2. 已发行的产品临时出现一个bug，需要立刻做hotfix；
  3. 此时不需要stash半成品，直接新建一个hotfix的worktree目录修复bug；
  4. 两个项目互不干扰，一边继续开发新功能，一遍修复线上bug；主目录保持main分支用于合并、评审代码。

核心命令

下面，以项目agentic-design-patterns为例进行演示，将项目clone到本地。

cd /e/testspace
git clone https://github.com/xindoo/agentic-design-patterns.git

添加worktree

给已有分支创建worktree

查看当前所有分支：

当前处于main分支，使用以下命令为dev分支创建一个新的工作目录：

git worktree add ../agentic-design-patterns--dev dev

新目录放在主目录同级。

可以看到，新目录agentic-design-patterns--dev 拥有完整的代码文件夹，并且与主目录共享同一个.git对象数据库，处于dev分支；

agentic-design-patterns仍处于main分支。

给新分支创建worktree

使用以下命令，创建新的分支feature/abc，并基于这个分支创建worktree工作目录：

git worktree add -b feature/abc ../agentic-design-patterns--feature-abc

查看所有worktree

使用以下命令，查看仓库中所有worktree：

git worktree list

输出会显示：目录路径、commit hash、绑定的分支名，快速看清哪个目录对应哪个分支，避免重复检出同一分支。

合并worktree分支

worktree 的分支合并和普通 git 合并完全一样：

  1. 在 feature 的 worktree 目录完成开发，提交所有改动；
  2. 切回主工作树目录，切换到 main；
  3. 使用 git merge 合并 feature/abc 分支；
  4. 解决可能的冲突，然后 push 到远端仓库。
# 在feature/abc 分支产生变更
cd ../agentic-design-patterns--feature-abc
echo "abc" >> README.md
git add README.md
git commit -m "add abc"

# 切回主工作树目录，切换到main分支
cd ../agentic-design-patterns
git checkout main

# 合并feature/abc分支
git merge feature/abc

# 解决冲突，然后push到远端仓库
git push origin main

删除worktree

任务完成后清理链接工作树：

git worktree remove ../agentic-design-patterns--feature-abc

注意：

  • 默认只能删除干净的工作区（无未提交改动），如果存在未提交，可使用--force强制删除；
  • 不能删除主工作树；
  • remove只会删除工作目录，不会删除对应的git分支本身；删除前建议先git status查看工作区状态，避免误删。

清理失效的worktree元数据

如果手动删除某个worktree目录，.git仍会保留旧的元数据，在git worktree list结果中会标记为missing状态。

此时可以使用下述命令清理：

# 清理所有失效的worktree记录
git worktree prune

# 只清理超过7天未使用的失效记录
git worktree prune --expire 7.days.ago

# 立刻全部清理
git worktree prune --expire now

优缺点总结

优点：

  1. 不用stash保存半成品代码；
  2. 多分支并行开发，不同目录独立编辑、运行；
  3. 共享git对象库，比多次clone仓库轻量（通过worktree创建的目录下不会有.git，只有主工作仓库下才存在）；
  4. 降低切错分支，误提交到错误分支的概率。

缺点：

  1. 每个worktree都会保存完整项目文件，会占用磁盘；
  2. 不能同一分支多次检出；
  3. 手动删除文件夹后，需要prune清理元数据。
