Git分支回退到上一个提交

2026/6/16 13:18:143 分钟阅读
Git

背景

在提交代码时，偶尔会发现自己在错误的分支（如受保护的dev分支）上进行了commit操作。此时需要对此提交进行回退。根据不同的场景可以使用不同的回退操作：

场景一：代码仅在本地提交，未推送到远端

这种场景下，通常可以采用软回退方式，保留变更的代码：

git reset --soft HEAD^

表示将分支的commit回退到上一个commit，代码保留在工作区，此时可以切换到自己的开发分支进行重新提交：

# 查看撤回的commit变更的文件
git status
# 切换分支
git checkout -b bug_fix_xxx
# 提交代码
git add .
# 提交信息示例
git commit -m "fix: 修复了xxxbug"

Note

--soft: 仅撤销提交的记录，修改的文件还在，可以重新commit

HEAD~1等价于HEAD^，若需回退多个，则使用HEAD~n，例如HEAD~2表示回退两个版本

硬重置

如果要彻底丢弃本地修改，commit和变更都撤销，则可以使用:

git reset --hard HEAD^

场景二：代码已经推送到远端，需要回退远端分支

注意，若远端分支是受保护的，能推送到远端说明具备此分支的修改权限。

方式A

reset后强制推送（多人协作慎用，会覆盖远端提交）：

git reset --hard HEAD^
git push -f origin 当前分支名

这里的origin以远端仓库源为准，可使用git remote -v查看。

方式B

使用revert生成新提交，生产环境首选，不删除历史提交：

# 自动生成一条新的commit，commit信息是撤销上一次提交的改动，历史保留
git revert HEAD
git push -f origin 当前分支名
