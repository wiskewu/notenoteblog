gitlab配置PAT避免每次https鉴权

2026/9/23 19:11:337 分钟阅读
Gitgithub

背景

当使用https协议克隆和管理项目仓库时，每次执行git pull、git push都需要重复输入Gitlab用户名和密码，开发体验极差。

虽然很多开发者会选择切换到ssh协议规避此问题，但在企业内网中，大部分网络配置管理员会封禁 SSH 端口，仅开放 HTTPS 443 端口。同时，https协议兼容性更强，无需配置密钥，是企业团队主流使用方式。

这篇文章主要介绍如何通过配置Personal Access Token(PAT) 来避免每次输入用户名和密码。

生成PAT

  1. 登录Gitlab账号，点击右上角头像，选择Edit Profile或Preferences，点击Access Tokens进入PAT配置页面。

  2. 在Token Name字段输入一个名称，Expiration date选择一个过期时间，Select Scopes按需选择（可以全选）。

  3. 点击Create personal access token生成PAT。

  4. 复制生成的PAT，妥善保存。

权限范围

作用域说明
apiAPI、代码推拉、镜像仓库全部权限
read_api允许调用 API去访问群组、仓库等
read_repository允许通过git拉取代码
write_repository允许通过git推送代码到仓库
read_registry允许读取容器镜像仓库
write_registry允许读写容器镜像仓库
read_user允许读取用户信息

配置Git凭证管理

Git 提供跨系统的凭证辅助工具，可将「用户名+PAT令牌」永久保存到系统自带的凭证仓库，不同系统配置命令不同，按需执行即可。

Windows 自带「凭据管理器」，执行全局配置命令，开启系统凭证存储：

# 全局配置凭证助手
git config --global credential.helper wincred

配置完成后，首次执行 git 操作时，输入：

  • 用户名：你的 GitLab 账号用户名/注册邮箱
  • 密码：前一步生成的 PAT 个人访问令牌

系统会自动保存凭证，后续永久免密。可在 控制面板 → 用户账户 → 凭据管理器 中查看、修改、删除 GitLab 凭证。

进阶配置glab

glab是 Gitlab 官方维护的 Git 命令行工具，支持 Gitlab、Github 等平台，功能强大，推荐使用。

在电脑按照完glab之后，可以按照下述步骤手动配置统一免密：

# 1. 先登录 glab（交互式绑定 GitLab 账号+令牌）
glab auth login

# 2. 配置 glab 为 Git 默认凭证助手（核心命令）
git config --global credential.helper "!glab auth git-credential"

这样配置的优势是：

  • 跨平台统一：无需区分 Windows/Mac/Linux 不同凭证命令
  • 凭证互通：glab CLI 操作、Git 推拉代码共用同一套 PAT 令牌
  • 自动续效：重新登录 glab 即可更新令牌，无需修改 Git 配置
  • 官方原生支持：完美适配 2FA、私有化 GitLab、公有云 GitLab

常见问题

配置优先级与冲突

正常优先级 glab git-credential 大于 系统凭证助手（wincred/osxkeychain）。

若配置失效，先清空旧凭证配置：

# 清空原有全局凭证助手
git config --global --unset credential.helper

# 重新配置 glab 凭证助手
git config --global credential.helper "!glab auth git-credential"

验证配置是否生效：

# 查看全局凭证配置
git config --global --list | grep credential

输出 credential.helper=!glab auth git-credential 即配置成功。

已有本地仓库适配免密

如果本地已有通过 HTTPS 克隆的仓库，无需重新克隆，直接执行操作即可，凭证管理器会自动适配新的 PAT 令牌。

若之前保存过错误凭证，先清除旧缓存：

# 清除当前仓库凭证缓存
git credential reject https://gitlab域名
