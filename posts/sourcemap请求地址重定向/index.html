SourceMap请求地址

常见的SourceMap在打包后，默认的形式是在JS产物文件末尾添加注释定义，例如index.js：

//# sourceMappingURL=index.js.map

表示 index.js 文件所在的同级目录处，还存在 index.js.map 源码映射。其文件关系如下：

dist
├── index.js
└── index.js.map

开发者工具查看请求地址

从浏览器开发者工具【更多工具-开发者资源】选项卡中，可以查看 SourceMap 的完整请求地址：

其中涉及的字段解释如下:

  • 网址（URL）: 完整SourceMap请求地址
  • 启动器（initiator）：是哪个JS文件发起的SourceMap请求
  • 总字节数（Total Bytes）：map文件的大小
  • 时长（Duration）：map文件请求时长
  • 错误（Error）：可能的404、跨域等失败原因

webpack修改SourceMap输出地址

前提条件，必须开启独立外部SourceMap，devtool设置为source-map以生成独立的.map文件：

// webpack.config.js
module.exports = {
  devtool: 'source-map', // 此时才会启用sourceMapFilename
}

场景一：输出到相对路径

假设需要让所有map文件输出到dist/sourcemaps目录：

// webpack.config.js
const path = require('path');
module.exports = {
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: 'js/[name].[contenthash].js',
    // map文件输出到 sourcemaps 文件夹
    sourceMapFilename: 'sourcemaps/[file].map'
  },
  devtool: 'source-map'
}

以上配置会：

  • 在磁盘输出dist/sourcemaps/app.xxx.js.map
  • 在JS文件末尾自动生成注释: //# sourceMappingURL=sourcemaps/app.xxx.js.map

场景二：输出为CDN/绝对域名地址

当map文件托管在独立 CDN，需要让 sourceMappingURL 输出完整 https 绝对地址，此时可以用插件，不再单纯依赖sourceMapFilename。

const webpack = require('webpack');
module.exports = {
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: '[name].[contenthash].js',
    // 磁盘输出路径
    sourceMapFilename: 'sourcemaps/[file].map'
  },
  devtool: false, // 使用插件时关闭内置devtool
  plugins: [
    new webpack.SourceMapDevToolPlugin({
      filename: 'sourcemaps/[file].map', // 磁盘输出路径
      // 自定义JS末尾的sourceMappingURL注释
      append: '\n//# sourceMappingURL=https://cdn.xxx.com/sourcemaps/[url]',
      // 给map自动拼接CDN前缀
      publicPath: 'https://cdn.xxx.com/'
    })
  ]
}
  • [url]: 会自动替换成 sourcemaps/app.js.map
  • 最终 JS 注释：//# sourceMappingURL=https://cdn.xxx.com/sourcemaps/app.js.map

场景三：同域名静态资源使用publicPath

如果项目静态资源统一 CDN，直接配置 output.publicPath，无需插件。

module.exports = {
  output: {
    publicPath: 'https://cdn.xxx.com/assets/',
    sourceMapFilename: 'sourcemaps/[file].map'
  },
  devtool: 'source-map'
}

JS 注释自动拼接 publicPath: //# sourceMappingURL=https://cdn.xxx.com/assets/sourcemaps/app.js.map

使用场景

在开发过程中，可能会对线上的js文件进行代理以进行本地调试，但此时调试源码时使用的依然是旧的 SourceMap，导致断点不准确、源码不正确等问题。此时就可以通过修改 SourceMap 的 URL 地址，将 SourceMap 请求重定向至本地代理环境，以实现js模块和源码映射的版本关系匹配。
